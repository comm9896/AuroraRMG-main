1. ОПИСАНИЕ ПРОБЛЕМЫ
================================================================================

Кнопка "Редактор" (BtnEditor) в главном окне открывает визуальный редактор зон
(TemplateEditorWindow). В этом редакторе пользователь может выбрать зону или
связь и отредактировать их свойства в инспекторе (InspectorFields).

ОШИБКА: данные, введённые в текстовые поля инспектора, НЕ СОХРАНЯЮТСЯ при
нажатии кнопки "Сохранить .rmg.json" (BtnSave), если пользователь не нажал
Enter и не переключил фокус с поля ввода перед сохранением.

2. КОРНЕВАЯ ПРИЧИНА
================================================================================

Файл: TemplateEditorWindow.xaml.cs

Методы AddTextField (строки 397-404) и AddComboField (строки 406-415) привязывают
логику сохранения значения ТОЛЬКО к двум событиям:

  - LostFocus  — поле потеряло фокус (клик куда-то в другое место)
  - KeyDown    = Enter (только для AddTextField)
  - SelectionChanged (только для AddComboField)

Проблема в том, что при клике на кнопку "Сохранить" (BtnSave_Click) фокус
переходит на кнопку, а НЕ на другое место внутри панели инспектора. Однако
в WPF при клике на кнопку в тулбаре (который находится в другом контейнере)
LostFocus на TextBox срабатывает, и значение должно записаться.

НО — есть более серьёзная проблема: при клике на кнопку "Сохранить" диалог
SaveFileDialog модально блокирует окно. В этот момент порядок событий WPF
таков, что LostFocus может сработать ПОСЛЕ того, как BtnSave_Click уже начал
выполняться, либо вообще не сработать из-за модального диалога.

Однако ГЛАВНАЯ ОШИБКА находится в другом месте:

3. ОСНОВНАЯ ОШИБКА: Значения НЕ записываются в модель при потере фокуса
   в определённых сценариях
================================================================================

Посмотрим на цепочку вызовов при сохранении:

  BtnSave_Click (строка 826)
    → валидация
    → SaveFileDialog.ShowDialog()
    → JsonSerializer.Serialize(_template, JsonOptions)

Объект _template сериализуется напрямую. Значения из инспектора должны быть
записаны в свойства Zone/Connection через onCommit колбэки.

Проблема: если пользователь ввёл значение в TextBox и сразу нажал "Сохранить",
не нажимая Enter и не убирая фокус — колбэк onCommit НЕ вызовется, потому что:

  a) LostFocus ещё не произошёл (фокус всё ещё на TextBox)
  b) Модальный SaveFileDialog "перехватывает" фокус, но LostFocus на TextBox
     может сработать уже ПОСЛЕ закрытия диалога, когда сохранение завершено.

  В результате: в сохранённый .rmg.json попадает СТАРОЕ значение, а новое — нет.

4. ДОПОЛНИТЕЛЬНАЯ ПРОБЛЕМА: Отсутствие принудительного коммита при сохранении
================================================================================

Метод BtnSave_Click НЕ вызывает принудительное сохранение (commit) текущего
редактируемого поля перед сериализацией. Правильное решение — добавить вызов
Keyboard.ClearFocus() или FocusManager.SetFocusedElement() перед сохранением,
чтобы принудительно вызвать LostFocus и записать значение в модель.

5. РЕКОМЕНДУЕМОЕ ИСПРАВЛЕНИЕ
================================================================================

В файле TemplateEditorWindow.xaml.cs добавить принудительный коммит перед
сохранением. Например:

  private void BtnSave_Click(object sender, RoutedEventArgs e)
  {
      // ПРИНУДИТЕЛЬНЫЙ КОММИТ: снимаем фокус с текущего поля ввода,
      // чтобы LostFocus сработал и записал значение в модель.
      Keyboard.ClearFocus();
      // Или: FocusManager.SetFocusedElement(this, null);

      // ... далее существующий код валидации и сохранения ...

Аналогично для BtnLoad_Click (строка 795) — при загрузке нового файла
несохранённые значения инспектора будут потеряны.

6. ВТОРАЯ ПОТЕНЦИАЛЬНАЯ ПРОБЛЕМА: Доступ к варианту через индекс [0]
================================================================================

Свойство Variant (строки 88-96) всегда возвращает _template.Variants[0].
Если при загрузке .rmg.json файла вариантов нет (Variants == null или пустой),
создаётся новый пустой Variant. Это корректно.

Однако если в файле несколько вариантов, редактор работает только с первым.
Это не баг, а ограничение дизайна, но стоит учитывать.

8. ИТОГ
================================================================================

Главная ошибка: при вводе данных в текстовые поля инспектора и немедленном
нажатии "Сохранить" данные не записываются в модель, потому что событие
LostFocus не успевает сработать до начала сериализации.

Исправление: добавить Keyboard.ClearFocus() в начало BtnSave_Click() (и
BtnLoad_Click()), чтобы принудительно вызвать потерю фокуса и записать все
несохранённые значения из полей ввода в объекты модели перед сохранением.
